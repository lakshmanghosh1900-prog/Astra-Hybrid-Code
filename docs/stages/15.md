# Stage 15 — Benchmark Harness

## Acceptance criteria

- [x] A versioned internal suite contains exactly 70 tasks across representative categories.
- [x] Results record verified success, tokens, repairs, duration, and failure class.
- [x] Reports are machine-readable and human-readable.
- [x] The harness rejects duplicate/unknown task IDs and does not turn an absent agent into success.
- [x] A baseline report is saved under `docs/benchmarks/`.

## Implementation

Added `astra_coder.benchmark` with ten categories and seven deterministic fixture tasks per category. The harness checks task identity and produces JSON/Markdown reports. It deliberately distinguishes a 70/70 contract-smoke run from the honest no-agent baseline.

## Evidence

```text
.venv/bin/python -m pytest
# 66 passed (3 dependency deprecation warnings)
.venv/bin/python -m ruff check src tests
# passed
.venv/bin/python -m ruff format --check src tests
# passed
.venv/bin/python -m mypy src
# Success: no issues found in 17 source files
PYTHONPATH=src .venv/bin/python -m astra_coder.benchmark
# wrote contract-smoke and agent-baseline reports
```

The contract-smoke report is not a coding-agent quality claim. The agent baseline reports 0/70 because a full autonomous executor is not yet wired into the service; this prevents a false benchmark success.
