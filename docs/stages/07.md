# Stage 07 — Secure Sandbox

## Acceptance criteria

- [x] Docker command construction includes network none, read-only root, cap-drop ALL, no-new-privileges, non-root user, resource limits, and a bounded writable workspace.
- [x] Commands are argv-based and have no shell interpolation.
- [x] Timeout results are machine-readable and the runner fails closed.
- [x] Docker unavailability never falls back to host execution.
- [x] Tests cover the security flags, timeout result, and unavailable daemon behavior.

## Implementation

Added `astra_coder.sandbox` with a typed Docker command contract, explicit network/read-only/capability/no-new-privileges/user/resource flags, bounded timeout handling, capped output, and fail-closed Docker-unavailable behavior.

## Evidence

```text
.venv/bin/python -m pytest
# 37 passed
.venv/bin/python -m ruff check src tests
# passed
.venv/bin/python -m ruff format --check src tests
# passed
.venv/bin/python -m mypy src
# Success: no issues found in 10 source files
```

The Docker daemon is unavailable in this environment, so integration execution was not claimed. Command construction and timeout/unavailable behavior are verified with a fake runner.
