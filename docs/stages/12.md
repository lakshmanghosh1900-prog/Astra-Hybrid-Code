# Stage 12 — Persistence & Audit

## Acceptance criteria

- [x] SQLite persists task state and bounded runtime counters.
- [x] Audit events are append-only application records with sequence/hash chaining.
- [x] Sensitive metadata values are redacted before storage.
- [x] Events can be replayed by task target and chain tampering is detected.
- [x] Restart recovery fails interrupted execution closed and requires re-verification. Never-claimed queued work remains queued for the worker to claim.
- [x] Tests cover persistence, redaction, tamper detection, replay, and recovery.

## Implementation

Added `astra_coder.persistence` with SQLAlchemy 2 SQLite task storage, durable runtime counters/limits, process-restart fail-closed recovery, append-only sequence/hash-chained audit events, redaction, replay, and tamper verification.
