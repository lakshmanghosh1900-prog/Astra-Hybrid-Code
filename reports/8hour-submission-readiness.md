## Reproducible demo checklist

### Preferred target: clean Linux checkout with Docker

Use a clean checkout containing the intended committed `HEAD`. Do not use
`git reset`, `git clean`, or any destructive cleanup in the active workspace.

```sh
git status --short                 # review; do not proceed as “clean” if unexpected
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.lock
docker info --format '{{.OSType}}' # expected: linux
docker compose --profile worker build api dashboard worker
python scripts/worker_smoke.py
```

Expected evidence:

1. Docker reports `linux` and all three images build.
2. The script prints `PASS: real worker flow; positive=<id> negative=<id>`.
3. `reports/worker-smoke.json` has `"status": "passed"`.
4. The positive task is `succeeded` with tests, Ruff, and Mypy passed; the
   deliberately incorrect task is `failed` on independent tests.
5. The artifact records original-repository preservation, 401/403 controls,
   kill-switch denial, result-hash durability, and audit-chain verification.
6. The script stops services but retains containers/volumes. It does not prove
   security scanners, model quality, production isolation, or eligibility.

The smoke script can take several minutes and rewrites
`reports/worker-smoke.json`; preserve the current artifact before a deliberate
rerun. Run it only from the intended clean committed checkout because it seeds
from committed `HEAD`.

## Recovery and stop conditions

| Situation | Safe response |
|---|---|
| Docker is unavailable, not Linux, or image build fails | Stop and mark the worker demo **BLOCKED**. Do not run agent commands on the host and do not convert old evidence into a current pass. |
| The smoke script fails | Preserve its JSON output and logs, record the first failing gate, and report failure. Do not delete volumes or reset the source checkout. |
| The source checkout is dirty | Use a separate clean checkout for the demo. Never reset or clean the active workspace. |
| `reports/worker-smoke.json` already exists | Preserve it before any deliberate rerun; the script overwrites that path. |
| A scanner or provider is missing | Record **BLOCKED/UNAVAILABLE**. Missing scanners are not successful security evidence, and no model claim is possible without a real provider call plus artifact verification. |
| API health is green but task is queued | Say “accepted into the queue, not executed.” Health only proves API process availability. |

Services may be stopped with the same Compose project after a demo; retain
volumes and evidence. Do not use `docker compose down -v`, `git reset --hard`,
or `git clean` in or for the active workspace.
